# Reporting a vulnerability

Please report security issues privately rather than opening a public issue.

- Open a [private security advisory](https://github.com/bissellator/quickieweb/security/advisories/new)
  on this repository, or
- email **security@quickieweb.com**

Please include what you did, what happened, and what you expected. A proof of
concept helps enormously; so does telling us which version or commit you were on.

You will get an acknowledgement within a few days. If a fix is warranted we will
work on it in private and credit you in the advisory unless you would rather we
did not.

## Scope

This repository, and the hosted service at quickieweb.com.

Findings in **your own** self-hosted installation are yours to fix, but if the
cause is a default in this code — a permissive policy we ship, a script that
grants more than it needs — that is very much in scope and worth reporting.

## What we already know

`docs/SECURITY.md` documents the security model and, at the end, a list of known
gaps. Something already listed there is not a new finding, though a demonstration
that one is worse than we think certainly is.

## Not in scope

- Missing headers or configuration on a deployment we do not run.
- Reports generated by a scanner with no accompanying analysis.
- Denial of service by volume against your own AWS account.
